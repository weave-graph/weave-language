## Cross-project acceptance still missing

The current composed-value fixture proves a useful narrow path: source graphs → temporal join → parameterized filter → second join → final graph with leaf provenance. It does not prove offline/mobile behavior, live views, general reasoning, recursive metadata cycles, full authorization, clustering, geometry or governance.

The complete offline-phone story still needs evidence-graph editing, offline local execution, authorized reactions, portable history exchange, conflict preservation, explicit governance acceptance and explainable accepted outputs. Duplicate events, unavailable dependencies and revoked authority must be tested in the same end-to-end scenario. Engine-only capsule tests must not be reported as language or mobile conformance.

## Public-release readiness versus full-design completion

A public experimental GitHub source release can proceed with clearly documented gaps, MIT notices, reproducible source builds and passing public CI. It does not require pretending the full design is complete. The original requested project completion remains open until the relevant requirements pass their gates or the owner explicitly amends scope.

`cargo package`/crates.io publication is not the current distribution path: Cargo excludes nested package contents and strips path dependencies when packaging. This repository is marked `publish = false` until a coordinated optional registry release exists. Git clones and `git archive` include the standalone vendored contract and can build or install with `cargo install --locked --path .`. Do not describe a `.crate` package as self-contained.

The audit does not establish a minimum supported Rust version below the tested 1.94.0, browser runtime support from a WASM check, success on an unrun CI platform, or a configured private security-reporting channel. Those are explicit evidence gaps, not implied capabilities.
