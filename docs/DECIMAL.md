# Exact decimal library profile

The recovered language paper §4 includes decimals and typed quantities in the core value family; it does not select a precision, canonical representation or rounding policy. This bounded implementation choice is an independent language library module, `weave_language::decimal`. Protocol 0.12 adds explicit source literals and an exact scalar schema variant. Nominal Quantity values and pure literal rational scaling reuse this type; an authenticated graph conversion service and full unit algebra remain open. Existing Float remains finite IEEE 754 binary64.

`Decimal` is exactly `coefficient × 10^-scale`, with an absolute coefficient at most `999999999999999999` and scale from 0 through 18. Fields are private. Fractional trailing zeroes are removed; zero has a unique representation. The range is symmetric, with maximum absolute value `999999999999999999` and smallest nonzero magnitude `0.000000000000000001`. Some values inside that range still require more than 18 coefficient digits and are rejected.

The parser accepts an optional sign, required decimal digits, an optional fractional part with required digits, and an optional signed base-ten exponent. Input is limited to 128 bytes and exponent magnitude to 128. It accepts spelling variants such as `+0012.3400e-1`, normalizing that value to `1.234`. Whitespace, separators, NaN, infinity and missing digits are errors. Precision and scale limits apply after exact normalization.

Canonical display uses ordinary decimal notation, without an exponent, redundant leading/trailing fractional zeroes or negative zero. Serde encodes a string, preserving integers beyond binary64's exact integer range. Deserialization accepts only canonical string values, rejecting JSON numbers and strings such as `1.20`. This canonicalizes the decimal value, not arbitrary enclosing JSON byte spelling. The containing decoder must still enforce its overall input limit; this module bounds its own parser work and avoids an extra owned-string copy.

`checked_add`, `checked_sub` and `checked_mul` calculate exactly, normalize and then check representability. `checked_div` reduces the fraction and accepts only denominators whose remaining factors are 2 and 5 and whose exact quotient fits the profile. Division by zero, nonterminating decimal expansion, scale overflow and coefficient precision overflow are explicit errors. There is no implicit rounding, saturation or conversion through Float. Callers cannot assume algebraically equivalent expressions will all fit intermediate result limits.

The implementation uses standard Rust integers without additional dependencies. Addition alignment and multiplication need at most 37 decimal digits, below signed i128 capacity. Division reduces factors before expansion and uses checked multiplication. Precision failures do not wrap. All loops are bounded by the 128-byte parser limit, 18-digit coefficient range or denominator factor count. General high-precision arithmetic and rounded division remain separate work. The canonical implementation now lives in the vendored contract and the language decimal module reexports it.

`tests/decimal.rs` checks canonical encoding beyond `2^53`, zero normalization, malformed and bounded input, cancellation across scales, overflow, underflow, exact/nonterminating division and an independent rational grid of 6,561 operand pairs. It does not substitute for future quantity/unit, source typing or runtime conformance tests.
