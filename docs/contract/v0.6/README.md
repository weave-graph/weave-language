# Weave compiler/runtime contract 0.6.0

This version separates structural relationship identity from source-assertion identity and carries source function revisions through program/result envelopes. Versions 0.1–0.5 remain accepted under their existing feature gates. Explicit-profile graph data and source revision manifests require 0.6.

`GraphData.profile` defaults to `legacy`. A legacy graph retains its earlier `edges` representation. An `explicit` graph instead contains `structural_edges` and `assertions`; its legacy `edges` array must be empty. Each structural relationship fixes its occurrence ID, predicate and endpoints. Each assertion has its own ID, referenced structural edge, claimed source label, optional context reference, polarity, valid interval, properties, metadata and visibility. No assertions means no asserted evidence, even when structural relationships exist. Profiles cannot be silently mixed.

Queries materialize each authorized assertion as a graph-value edge whose ID is the assertion ID. `structural_ref` preserves the exact graph/revision/structural-edge identity; `assertion_source`, `assertion_context` and `assertion_properties` preserve attribution separately from structural `properties`. Pinned assertion provenance identifies source assertions. Named attachments can target structural edges or individual assertions; host-path dependencies retain the original attachment identity through materialization. Schema edge declarations validate structural relationships without inventing claims.

Source and context labels are recorded data, not authenticated origin evidence or authorization grants. Contextual claims can be queried, projected and unioned. Support and join reject matching contextual premises with `E_CONTEXT_REQUIRED` until an explicit compatible context-selection/broadcast rule exists. Context applicability is an open required gate, not silently assumed universal.

`Program.source_revisions` and `QueryResult.source_revisions` carry source name, declared revision and normalized digest. Compiler normalization removes only known AST location fields; arbitrary literal keys named `span` remain semantic. These manifests preserve attribution and computation identity, without authenticating the source author.

The portable `identity` module provides expression/program fingerprints, full-result fingerprints under trusted principal/policy context, and graph-valued explanations of already authorized results. Structural IR order is retained, including ordered effects. Schema/source/dependency collections use canonical membership ordering. Full-result identity includes origin maps, provenance, coverage, diagnostics, schemas, source revisions and data; display array order remains significant. This is deterministic structural identity, not minimal algebraic equivalence. Host-supplied policy revision, identity mappings and artifact identities cannot be manufactured by executable plans.

Explanation graphs expose separate alternative and joint-premise arcs, scoped to the current principal. Every explanation edge retains exactly its own alternative's premise group and operator parameters. Generated nodes use opaque derived identities and empty source-origin envelopes rather than invented persisted node references. Explanations compose with graph algebra and enforce object/byte limits during construction. They are immutable observations of authorized inputs; they do not recall plaintext already disclosed. Source-level `explain`, complete policy-aware cache lifecycle and general rule evaluation remain separate work.
